# SMT Local Monitoring

Актуальное состояние на 2025‑12.

## Что это
- Локальный телематический стек (ingest → хранение → WEB/бот) без завязки на внешний кэш Wialon.
- Источники: Wialon IPS, Galileosky (push), можно комбинировать через `PIPELINE_SOURCE_LIST`.
- **PostgreSQL — единственный источник правды** для телематики: `events`, `trips`, реестра устройств (`units/devices/unit_device_links`), конфигов (`unit_configs`) и иерархии (`nodes/users/units_meta`).
- Все UI‑слои (WEB/бот) работают только с локальными данными из Postgres; файловое хранилище (`RawStorage`) используется как cold‑архив и не читается в горячем пути.

## Требования
- Python 3.12+, virtualenv `.venv`.
- Postgres (таблицы `events`, `trips`, registry) — `DEVICE_REGISTRY_DSN` или `DATABASE_URL`.
- Redis — курсоры trip_worker и Shadow/Inbox (`REDIS_URL`).

## Быстрый старт

### 1. Backend (API + ingest + бот)
```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements-dev.txt

# минимальный локальный запуск без туннеля (для отладки UI)
export DEVICE_REGISTRY_DSN='postgresql://smt_user:smt_password@127.0.0.1:5432/smt_telematics'
export REDIS_URL='redis://127.0.0.1:6379/0'
SKIP_TUNNEL=1 WEB_PORT=8000 ./scripts/start_galileosky_stack.sh

# в бою вместо SKIP_TUNNEL=1 используется реальный TUNNEL_HOST/TUNNEL_USER в .env
```
Порты по умолчанию: web 8000, IPS 18081, Galileosky 8088.

### 2. Frontend (SPA Monitoring)

```bash
cd web-ui
npm install        # первый раз
npm run dev        # http://127.0.0.1:5173
```

Логин по умолчанию для веб‑мониторинга: `admin / admin` (создаётся скриптом `init_admin.py`).

## Поток данных
- `pipeline/cli/run_stream.py` пишет события в Postgres `events` (primary storage) и в `data/pipeline_storage/<YYYY-MM-DD>/events*.jsonl` как cold‑архив.
- `pipeline/cli/run_trip_worker.py` читает `events`, хранит состояние в Redis, пишет поездки в `trips`.
- WEB‑backend (`pipeline/api/web_app.py` + `pipeline/api/web_v2.py`) отдаёт JSON‑эндпоинты под префиксом `/web/api/...`; данные берутся из `events/trips/LatestTelemetryStore/unit_configs`.
- Фронтенд Monitoring реализован как отдельный SPA в каталоге `web-ui/` (Vite/React), который ходит в эти JSON‑эндпоинты.
- Shadow/Inbox: Redis + методы в `pipeline/api/web_v2.py` (управление незарегистрированными устройствами).

## Если нет поездок в UI
1. `psql "$DEVICE_REGISTRY_DSN" -c "select count(*) from events;"`
2. `psql "$DEVICE_REGISTRY_DSN" -c "select count(*) from trips;"`
3. Если events только в файлах — импортируй:
   ```bash
   .venv/bin/python scripts/import_events_to_db.py
   ```
4. Убедись, что run_stream и trip_worker запущены и используют один DSN/Redis.

## Полезные команды
- Запуск всего стека (bot + stream + web) одной командой:  
  `PYTHONPATH=. .venv/bin/python pipeline/cli/run_all.py`
- Только web: `PYTHONPATH=. uvicorn pipeline.api.web_app:app --host 0.0.0.0 --port 8000`
- Только ingest: `PYTHONPATH=. .venv/bin/python pipeline/cli/run_stream.py --units cached`

- Импорт событий в БД: `.venv/bin/python scripts/import_events_to_db.py`

## Текущее состояние реализации (2025‑12)

**Backend**
- Полностью переведён на SQL‑first: все боевые данные (events, trips, units/devices, unit_configs, nodes/users/units_meta) живут в PostgreSQL.
- `PipelineStorageService` читает/пишет только в БД (плюс архив в `RawStorage`); никаких чтений JSON‑файлов в горячем пути.
- `AdminStorage`/`UnitConfigService` работают через те же DSN, что и ingest/API; `web_admin.sqlite3` и файловые конфиги не используются.
- `run_stream.py` и источники (Wialon IPS / Galileosky) пишут события через общий сервис; `LatestTelemetryStore` используется только как кэш «последних точек».

**Frontend (Monitoring SPA)**
- Реализована Phase 1 «The Living Map»:
  - карта на MapLibre в тёмном стиле на весь экран;
  - маркеры двигаются императивно через `requestAnimationFrame` (hook `useAnimatedMarker`), без ре‑рендеров React на каждом кадре;
  - иконка ТС фиксирована, направление движения отображается отдельной стрелкой/орбитой.
- Реализована Phase 2 «The Floating Dock»:
  - стеклянная плавающая панель слева (`FloatingPanel`), в которой:
    - виртуализированный список объектов (`react-virtuoso`) с поиском и счётчиками;
    - карточка объекта (`UnitDetails`) с плавной анимацией перехода (Framer Motion);
  - двусторонняя связь карта ↔ список:
    - клик по строке фокусирует карту на объекте и раскрывает карточку;
    - клик по маркеру выбирает тот же объект в доке;
    - ховер в списке и на карте синхронизируется (подсветка и тултипы).
- Apple‑style multi‑select (Morph):
  - аватарка строки плавно превращается в чекбокс (иконка растворяется, галочка проявляется, фон перекрашивается), без «клоаки» и скачков;
  - режим «Выбрать» не открывает карточку, даже если выбран один объект; карточка показывается только вне режима выбора;
  - карта понимает многократный выбор: авто‑кадр по группе, «Следить (N)» как отдельная кнопка, клик в пустоту/ESC снимает фокус; тост Shadow Inbox поднят выше (bottom‑32), чтобы не перекрывать управление.
- HUD снизу экрана (`MapHUD`): единый стек (`flex-col-reverse`) для плавающей кнопки слежения и тоста Shadow Inbox; follow-кнопка появляется при сорванной камере, тост автоматически занимает её место.
- Следующий шаг (Phase 2.5) — обогащение карточки визуальными виджетами (топливо‑гейдж, спидометр, мини‑трек) поверх существующего API `/api/units/{id}` и `/api/history/*`.

## Манифест разработки / Vision

### PROJECT CONTEXT: SMT NEXT-GEN (Situation Awareness Platform)

Мы строим систему мониторинга транспорта, которая должна уничтожить стандарты рынка (Wialon, Omnicomm) за счёт превосходства в UX и инженерии.  
Это не «учётная система». Это **Ситуационный Центр (God Mode)** для управления флотом.

### 1. Философия продукта

Мы отказываемся от парадигм 2010‑х годов (статичные сайдбары, модальные окна, таблицы, деревья галочек).

Цель в простых словах — быть «Apple в мире СМТ»: продуктом, где инженерия, UX и визуальное исполнение на порядок аккуратнее и честнее рынка, а каждая деталь сделана намеренно, а не «как получилось».

**Принципы:**

1. **Map as a Desktop.** Карта — не подложка, а рабочий стол. Она занимает 100% экрана (`z-index: 0`). Весь UI — плавающие полупрозрачные инструменты (HUD) поверх карты.
2. **Context Over Clicks.** Пользователь не должен кликать, чтобы узнать статус. Он видит его периферийным зрением (цвет, анимация, умный зум).
3. **Progressive Efficiency (Low Floor, High Ceiling).** Интерфейс должен быть на 100% понятен новичку, который использует только мышь. Каждая функция доступна через UI. Для каждого действия есть «путь профессионала» (Global Search, hotkeys), позволяющий опытным диспетчерам работать в разы быстрее. Принцип: «Легко начать, невозможно разлюбить».
4. **Fluid Interfaces.** Никаких резких появлений. Всё выезжает, трансформируется и растворяется (physics‑based анимации).

### 2. Технический стек (целевой)

**Frontend (SPA):**

- React + TypeScript + Vite.
- MapLibre GL JS — векторная карта (никакого Leaflet).
- Tailwind CSS — базовая система стилей.
- Framer Motion — сложные анимации переходов (layout‑анимации).
- Zustand — стейт‑менеджмент без лишнего boilerplate.

**Backend (готов и «заморожен»):**

- Python (FastAPI) + PostgreSQL.
- Архитектура SQL‑First: единый источник правды, никаких файловых кэшей в горячем пути.
- API отдаёт чистый JSON (`/web/api/...` на бэкенде; через Vite‑прокси фронт обращается к `/api/...`).
- Ingest (Wialon IPS / Galileosky) работает в фоне и пишет в базу с минимальной задержкой, обновляя in‑memory `LatestTelemetryStore`.

### 3. UI/UX директивы (Frontend Roadmap)

**A. Layout: Floating Dock**

- Слева нет прибитого сайдбара. Есть **Floating Panel** (~360px шириной, отступ 16px).
- Стиль: **Glassmorphism** (`backdrop-filter: blur(12px)`, тёмный фон `bg-black/60`, тонкие бордеры).
- **List → Detail Transition:** при выборе объекта панель не перекрывается новым окном; список внутри панели плавно трансформируется в карточку объекта, а карта центрируется на объекте с учётом оффсета панели.

**B. Карта: Semantic Zoom**

- Иконки рисуются через WebGL‑слои MapLibre.
- На низком зуме — кластеры/точки‑статусы (зелёные/красные).
- На высоком зуме — детали (подписи, направление, скорость) прямо на карте.
- Tooltips — мгновенный hover без ощутимой задержки.

**C. Навигация: Command Center**

- Всегда видна строка поиска/кнопка действий.
- Глобальный перехват `Ctrl+K` / `Cmd+K` → Spotlight‑поиск в центре экрана.
- Поиск умеет: переход к объекту, переключение слоёв, открытие отчётов.

**D. Визуализация данных**

- Никаких скучных `key: value` таблиц.
- Топливо — визуальный индикатор (gauge/«батарейка»).
- Скорость — SVG‑дуга (спидометр).
- История — sparkline‑графики прямо в карточке.

## Backend & API Technical Landscape (для фронтенда)

Этот раздел описывает фактический контракт бэкенда. При разработке фронтенда:

- на стороне бэкенда маршруты живут под префиксом `/web/api/...` (см. `pipeline/api/web_app.py`);
- в `web-ui/vite.config.ts` настроен прокси `/api -> http://127.0.0.1:8000/web`, поэтому SPA обращается к путям вида `/api/...`.

### 1. Архитектура

- **Server:** FastAPI, порт `8000` (`uvicorn pipeline.api.web_app:app --port 8000`).
- **Database:** PostgreSQL — единый источник правды (events, trips, units/devices, unit_configs, nodes/users/units_meta).
- **Ingest:** `pipeline/cli/run_stream.py` принимает Wialon IPS / Galileosky, пишет в `events` и обновляет `LatestTelemetryStore`.
- **Real‑time:** Short polling по `/api/units/feed` (2–5 секунд); WebSocket‑ов пока нет.

### 2. Аутентификация

- Кастомные сессии (JWT нет).
- **Login:** `POST /api/login` с телом `{ "login": "...", "password": "..." }`.
  - Ответ: `{ "session_id", "login", "display_name", "is_admin", "node_id" }`.
  - Внутри backend‑сессии дополнительно хранится `user_id`, но он фронту не нужен.
- **Header:** все защищённые запросы должны содержать:

  ```http
  X-Session-Id: <session_id>
  ```

- При `401 Unauthorized` фронт должен:
  - очистить `localStorage`/кеш сессии;
  - показать форму логина.

### 3. API endpoints (основные)

Все пути ниже указаны в frontend‑виде (`/api/...` через Vite‑прокси).

**A. Units (список и состояние)**

- `GET /api/units` — список видимых объектов (с учётом прав пользователя).
  - Response: `UnitListItem[]` (id, name, online, status, status_label, last_ts, last_ts_age_sec, lat, lon, speed, has_fuel, ignition, offline_reason, sensor_tags, ...).
- `GET /api/units/feed` — лёгкий эндпоинт для поллинга.
  - Query:
    - `since` (опционально),
    - `watch_ids` (опционально, CSV id).
  - Response: `{ ts: number, updates: UnitFeedItem[], shadow_count: number }`, где `updates` содержит только изменившиеся юниты.
- `GET /api/units/{id}` — детальная карточка объекта.
  - Response: `UnitDetail` (общие поля, статус, конфиг sensors/advanced, последние параметры).

**B. History (треки и поездки)**

- `GET /api/history/track`
  - Query: `unit_id`, `from_ts`, `to_ts` (Unix‑timestamp).
  - Response: `TrackPoint[]` — `{ lat, lon, ts, speed }` для отрисовки polyline.
- `GET /api/history/trips`
  - Query: `unit_id`, `from_ts`, `to_ts`.
  - Response: `TripResponse[]` — поездки/остановки (start_ts/end_ts, distance_m, max_speed, адреса, duration_str).
- `GET /api/history/calendar`
  - Query: `unit_id`, `month="YYYY-MM"`.
  - Response: `Record<string, int>` — пробег по дням месяца.

**C. Admin / System**

- `GET /api/session` — информация о текущем пользователе (`SessionInfo`: session_id, login, display_name, node_id, is_admin).
- `GET /api/unknown_devices` — список неразобранных устройств (Shadow Service).
- `GET /api/unknown_devices/count` — их количество (для индикатора).
- `GET /api/admin/summary`, `GET/POST /api/admin/*` — вспомогательные ручки для настройки дерева `nodes/users/units_meta` (используются только в админ‑UI).

### 4. Data‑model (для типов фронтенда)

- **Статус:**
  - `online: boolean`
  - `status: "moving" | "stopped" | "stop" | "offline" | "park_ign_on" | "park_ign_off"`
  - `status_label: string` — локализованная строка («Движение», «Стоянка 5ч» и т.п.).
- **Координаты и скорость:**
  - `lat`, `lon: number | null` — если `null`, объект ещё не присылал валидные координаты.
  - `speed: number | null` — текущая скорость.
- **Время/возраст:**
  - `last_ts: number | null` — время последнего события (Unix‑timestamp).
  - `last_ts_age_sec: number | null` — возраст события.
- **Sensors/params:**
  - В `UnitDetail` датчики и параметры приходят в нескольких полях:
    - `params` / `prms` — сырые параметры события (`pwr_ext`, `dev_status`, `rs485_fls...` и т.п.).
    - `config.sensors` — описания сенсоров (тип, units, привязанный параметр).
  - Фронт должен уметь:
    - читать сырые params (`pwr_ext` для напряжения, `rs485_flsXX` для ДУТ);
    - маппить их к человекочитаемым названиям согласно `UnitConfig`.

### 5. Dev‑среда

- Бэкенд: `http://127.0.0.1:8000` (`uvicorn pipeline.api.web_app:app`).
- SPA: `web-ui/`, запуск `npm run dev` (обычно `http://127.0.0.1:5173`).
- В `web-ui/vite.config.ts` настроен прокси:

  ```ts
  server: {
    port: 5173,
    proxy: {
      "/api": {
        target: "http://127.0.0.1:8000",
        changeOrigin: true,
        // SPA вызывает /api/..., бекенд слушает /web/api/...
        rewrite: (path) => path.replace(/^\/api/, "/web/api"),
      },
    },
  }
  ```

- Фронтенд не рендерит Jinja2/HTML — он использует только JSON‑эндпоинты, описанные выше.

## Phase 1 Roadmap — «Первая кровь»

Прямо и жёстко: **90% телематических систем умирают, потому что начинают с "админки" и "отчётов"**.  
Пользователю плевать на формы пользователей и настройки. Первое, что он видит — **карту**.

Если карта тормозит, выглядит как Google Maps 2010 года, а машинки на ней телепортируются раз в 10 секунд — продукт мёртв, сколько бы фич туда ни запихнули.

Фаза 1 — только три фичи. Но они должны быть сделаны идеально.

### Фича №1: The Living Map (Живая карта)

**Цель:** экран должен выглядеть как живой организм, а не статичная картинка.

- Векторная подложка в dark‑стиле (MapLibre).  
  Дороги — тёмно‑серые, фон — почти чёрный, активные объекты — неоновые.
- Интерполяция движения:
  - backend отдаёт точки раз в 5–10 секунд;
  - frontend **плавно двигает** маркеры между обновлениями (без скачков);
  - поворот иконки — тоже плавный.
- Умная кластеризация:
  - на низком зуме — аккуратные кластеры с количествами;
  - на высоком — отдельные машины, читаемые иконки/направление/скорость.

**Критерий успеха:** можно 5 минут просто смотреть на карту, ничего не нажимая, и получать удовольствие от того, как «живёт» флот.

### Фича №2: The Floating Dock (Плавающий док)

**Цель:** убить классический «список объектов» сбоку.

- Layout:
  - никакого сайдбара на всю высоту;
  - только плавающая стеклянная панель с `backdrop-blur`, ширина ~360px, отступ 16px от края.
- Содержимое:
  - слева от строки — цветная точка статуса;
  - справа — мини‑sparkline (график скорости/движения за час).
- Трансформация (Magic Move):
  - клик по строке → список **морфится** в карточку объекта внутри той же панели;
  - кнопка «Назад» → карточка плавно сворачивается обратно в список;
  - никаких перезагрузок/flash‑экранов — используем анимации уровня Framer Motion.

**Критерий успеха:** переход «список → карточка → список» ощущается как физическое взаимодействие, а не как переход на другую страницу.

### Фича №3: Instant Context (Мгновенный контекст)

**Цель:** убить таблицы `key: value` в карточке объекта.

- Топливо:
  - визуальный «стакан» (liquid gauge / батарейка), а не сухое число;
  - мало топлива → индикатор красный; слив → мигает.
- Зажигание/двигатель:
  - не текст «Вкл/Выкл», а иконка двигателя;
  - при работе — лёгкое свечение/вибрация.
- Адрес:
  - кликабельная ссылка/элемент, а не голая строка.
- Мини‑трек:
  - прямо в карточке фоном рисуется путь за сегодня / последние N минут.

**Критерий успеха:** диспетчер понимает состояние машины (едет/стоит, заведена/нет, есть ли топливо) за 0.5 секунды, не читая текст.

### Что сознательно НЕ делаем в фазе 1

Всё ниже — **осознанно отложено** на следующие фазы:

1. Отчёты (XLS/таблицы, сложные фильтры).
2. Геозоны и их редактор.
3. Уведомления/алерты.
4. Плеер истории (replay поездок).

Фаза 1 отвечает за ощущение «God Mode» от карты и базовой карточки.  
Сначала — вау‑эффект и «живой» мониторинг, потом всё остальное.

## Phase 2 — Floating Dock, Multi‑Select, Shadow Inbox (реализовано)

Карта и док доведены до продакшен‑качества (декабрь 2025):

- **Двусторонняя связка карта ↔ список.** Ховер и клик подсвечивают объект на карте и в доке; клик в пустоту или Esc снимает фокус.
- **Императивная анимация маркеров.** Координаты двигает `useAnimatedMarker` через `requestAnimationFrame`; React не дёргает DOM → нет дрожания.
- **Мультивыбор (Morph).** Аватарка строки плавно превращается в чекбокс, фон перекрашивается, карточка **не** открывается в режиме выбора; камера умеет кадрировать группу и «Следить (N)» через отдельную кнопку.
- **Floating Panel / Glassmorphism.** Стеклянная панель (blur, тонкие бордеры, воздух), плавные Framer Motion переходы список ↔ карточка.
- **Shadow Inbox (новые устройства).** Виртуализованный список с полированными карточками, системный тост поверх карты, синяя CTA «Подключить», ghost‑кнопка «X», кастомный тонкий скролл. Массовый импорт батчами, индикатор прогресса, автопереход к созданному юниту.
- **Верстка управления.** Кнопка «Следить» центрирована по карте; тост «Новое устройство» отступает ровно на 16 px над ней (96 px от низа экрана). Никаких перекрытий и «зебры» из белых кнопок.

Следующий фокус (Phase 2.5): визуальные виджеты в карточке (спидометр, топливный gauge, мини‑трек) на существующих эндпоинтах `/api/units/{id}` и `/api/history/*`.
